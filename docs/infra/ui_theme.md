# UI Theme (shared CSS design tokens)

## What this does

The whole app shares one set of CSS design tokens (`:root` variables in `static/styles.css`) and a common set of component classes (`.card`, `.stat-card`, `.btn*`, `.sidebar`/`.nav-item`, `.side-panel`, `.modal-shell`, `.wizard-shell`, `.cs-menu`, `.drop-zone*`, `.toggle`) that every feature's view builds on. Whole-app visual/theme changes belong here rather than being force-fit into one feature's doc, since they're cross-cutting by nature.

## Architecture

Covered implicitly by the Changelog below — there is no separate living design-system spec; `static/styles.css`'s `:root` block itself is the source of truth for current token values.

(a project-management/file-manager UI), not literally "Ringku," but treated as the ground-truth reference since that's what was actually supplied.
- **Extracted design language from the screenshots**: vivid indigo/violet primary accent, soft lavender-grey page background, white cards with soft "floating" drop shadows, generously rounded corners everywhere (cards ~16-20px, buttons pill-shaped), a light/white icon-plus-label sidebar with a SOLID colored pill background on the active nav item (not a border/tint), big bold numbers in stat cards with small sparkline charts, avatar-badge stacks, donut/bar charts with a small color-coded legend.
- **Confirmed via AskUserQuestion**: whole-app-in-one-pass (not a single-view pilot first).
- **Implementation choice**: did this at the SHARED CSS DESIGN-TOKEN level in `static/styles.css` rather than hand-editing individual views — every view in this app already builds on the same `:root` variables + a common set of component classes (`.card`, `.stat-card`, `.btn*`, `.sidebar`/`.nav-item`, `.side-panel`, `.modal-shell`, `.wizard-shell`, `.cs-menu`, `.drop-zone*`, `.toggle`), so changing those propagates the new look everywhere automatically, with far less risk than touching hundreds of scattered inline `style="..."` attributes in `app.js`.
- **`:root` shadows restored**: `--shadow-card`/`--shadow-lg`/`--shadow-xl` had been explicitly set to `none` in an earlier session's deliberate flat-design pass, and were otherwise UNREFERENCED anywhere else in the file (dead variables) — restored to real soft multi-layer shadow values and wired them onto `.card`, `.stat-card`, `.side-panel`, `.modal-shell`, `.wizard-shell`, `.cs-menu`, `.btn-primary`, and `.toggle button.active` (none of these had a shadow declaration before this session at all).
- **Sidebar flipped from solid dark-purple to a light/white chrome**: `.sidebar` background `var(--purple-900)` → `#fff` + a right border; `.nav-item` text/icon color (icons use `stroke="currentColor"` so they follow the text color automatically) went from light-lavender-on-dark to dark-grey-on-white; `.nav-item.active` is now a SOLID indigo pill (`var(--purple-500)` + a soft shadow) replacing the old dark-purple-block-plus-inset-accent-bar; `.nav-item:hover` is now a soft indigo tint instead of a darker purple; `.section-label` darkened for legibility against the new light background. `static/index.html`'s hardcoded sidebar text (`text-white` brand wordmark, a `rgba(255,255,255,0.12)` divider, a hardcoded blue-grey status-text hex) all needed a matching flip since they were HTML-inline, not CSS-variable-driven, and would have been illegible against the new light sidebar otherwise.
- **Border radius bumped up throughout** for a rounder/softer feel: `.card`/`.stat-card` 12→16px, `.btn` 8→10px, `.btn-sm` 7→9px, `.icon-btn` 8→10px, `.toggle` 8→10px (its buttons 6→8px), `.drop-zone` 10→14px, `.drop-zone-lg` 14→18px, `.modal-shell` 14→18px, `.wizard-shell` 16→20px, `.history-actions button` 6→8px. **`.btn-primary` specifically made fully pill-shaped** (`border-radius: 999px`) — the reference's single most visually distinctive button treatment — while smaller/dense in-table action buttons deliberately stay moderately rounded (not full pill), since this app's toolbars/tables are far denser than the reference's spacious lifestyle-dashboard layout and a sea of small full-pill buttons side-by-side reads as visually noisy rather than polished.
- **Deliberately NOT touched**: verdict/status semantic colors (`badge-verified/review/not`, every `status-*` class) — those encode real meaning (approved/rejected/pending), not just decoration, so recoloring them purely for aesthetic match risked confusing users reading actual data. Also not touched: the newer feature panels built with raw inline styles directly in `app.js` (Walmart Catalog, MPN Check, Brand Check inputs, per this session's own established pattern of building new panels that way) rather than these shared CSS classes — those won't pick up the new look automatically and will read slightly plainer/older than the rest of the app until a separate pass sweeps their inline styles too; flagged to the user as optional follow-up, not done in this pass.
