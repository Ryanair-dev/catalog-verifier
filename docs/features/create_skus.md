# Create SKUs — SellerCloud integration
<!-- nav label "Create SKUs"; internal route/module still named create-po / create_po -->

## What this does

SKU-generation + bulk-import tool. Full analysis, naming rules, data divergences, and the verified SellerCloud REST API reference live in `create_po_design.md`. **Status:** BUILT + live-verified end-to-end against server **fml** — full **4-step wizard UI** (ported from a Claude Design mockup) + generator + file export. Export produces the **real SellerCloud templates** (`bulk` / `kits` / `amz shadows`), matched column-for-column and delivered as **three separate file downloads**. Reference snapshot: `SC data.xlsx`.

## Architecture

- **Client** (`client.py`): `get_sellercloud_client()` → bearer token (POST `/api/token`, cached) + `GET /api/Catalog` (paged, `pageSize` cap 50) + `Settings/Brands` + custom-export/queued-jobs. Catalog has **no server-side MPN/ASIN filter**, and there is **no export-all** (exports need explicit ProductIds).
- **Index (SPEED — 2026-07-10):** Create SKUs now builds the catalog index from a **local snapshot of `SC data.xlsx`**, NOT the live SellerCloud API. Root cause of the old slowness: SellerCloud's `/api/Catalog` is **~4s per 50-item page AND serialises requests per account** (concurrency doesn't help — verified), so a first-time brand pull took 4s (KYOCERA, 1 page) to minutes (large brands). Now `catalog_index.local_index()` reads `data/sc_snapshot.json` (built once from the xlsx via `refresh_snapshot()`; 99.8k rows) and builds a full `CatalogIndex` in ~0.7s, cached in memory → **full generate+export ≈ 0.15s** (was 17s+). Source path is hardcoded (env `SELLERCLOUD_SNAPSHOT_PATH` overrides): `…FordMed\…\Offer Analytics Requests\SC data.xlsx` — "Sku Data extended" sheet = all SKUs (mostly mains: ProductID/UPC/ManufacturerSKU/Manufacturer/ASIN/BrandName/ShadowOf), "FBA" sheet = FBA/FBM shadow SKUs + ASIN. Reading the JSON (not the xlsx) at runtime avoids the file being locked/open in Excel. Refresh after a new catalog dump: `python -m services.sellercloud.catalog_index --snapshot`. Router uses `ci.local_index()` in `/brands` + `/generate`; `catalog_brand_names` now comes from `index.brand_names`; `/preview` no longer requires SellerCloud. TRADEOFF: the snapshot is static → a SKU created since the dump won't be seen (small duplicate risk) until refreshed or Azure is wired. The live per-brand path (`build_for_brands`, `data/brand_slices/` 12h cache) is retained for the CLI only. **Superseded 2026-10-07e**: `routers/create_po.py` now uses **Azure-only** live catalog lookups with no local-snapshot fallback (raises a clear error instead of silently degrading) — the snapshot repeatedly caused real bugs (56-day staleness, a persistently-Excel-locked source file). The snapshot mechanism above is retained for the CLI build tool only. Azure itself is refreshed hourly (`azure_sql.start_scheduler()`, 2026-10-07c) — see `docs/infra/azure_sql.md`.
- **Index** (`catalog_index.py`, live path — CLI only): built from **per-brand slices** (`model.brandIds`), cached to `data/brand_slices/` (12h). Indexes UPC/MPN/ASIN/SKU; prefix = mode of a brand's main SKUs **with a confidence share** (low = ask, don't guess). Existence is scoped to loaded brands. `keyword` matches ASIN but not MPN → MPN existence via the index.
- **Existence/generation model:** match incoming UPC/MPN against the index (don't rebuild the SKU string); shadows reuse the per-ASIN SKU or climb `-FBA2/3…` on collision. Imports are async (poll `/api/QueuedJobs`; status `3` = done). A main SKU lookup (`_main_exists`) is brand-scoped since an MPN alone is not globally unique across manufacturers — a brand filter prevents coincidental part-number collisions. Disabled SellerCloud SKUs and non-Merchant (`FulfilledBy != "Merchant"`) rows are excluded from being treated as mains, and from the index entirely when Disabled. When several active, Merchant, convention-matching candidates still exist, `_pick_main` prefers the one whose ProductID exactly matches the conventionally-generated `base_main`.
- **Wizard UI** (`static/create_po.js` + `static/create_po.css`, mounted into `#view-create-po` by `app.js` `initCreatePo()`; the mockup's sidebar is intentionally dropped): 4 steps — Upload → Configure & Map → Generate → Review & Export. `.cpo`-scoped styling (Bricolage Grotesque + Plus Jakarta Sans) on the **standard app palette** (grey-50 window + white cards, light-only) so it matches every other view, stepper, per-column mapping on an inline preview of the **actual uploaded sheet** (separate **Batch-type** and **Create-by** toggles), brand-roster table (single-brand vs mapped-column), inline-editable review board, export bar. Fills the pane (`#view-create-po{height:100%}` + `.cpo{min-height:100%}`). Self-contained module (`window.CreatePO.mount` / `.refresh`); no confidence scores (dropped per design).
- **Theme:** light-only, using the app's standard palette (grey-50 window + white cards) so Create SKUs matches every other view. (An earlier sidebar light/dark toggle was removed per user request — no `#theme-toggle`, no `data-theme` dark CSS.)
- **UI details:** all Create PO dropdowns use a styled custom `dd()` helper, not native `<select>`. The open menu is **portaled to `<body>`** (`id="cpo-portal"`, positioned in `afterRender()` from the trigger's viewport rect) so it can't be clipped/mispositioned by `#view-create-po`'s transform (the app's `view-enter-anim`) + overflow scroll — an earlier fixed-inside-the-tree menu silently rendered at `opacity:0` and off-screen, so clicking a dropdown appeared to do nothing. A document-level `onDocClick` handles option-picks + outside-close (the menu lives outside `S.root`); `render()` calls `removePortal()` first. Re-renders preserve `scrollTop` and gate the entrance animation to first mount (`.cpo-anim`) so toggling an option doesn't flash the page. Step 1 blocks **Configure & map** until required fields are mapped. **Step-1 layout:** two blocks — (1) `smallFilePreview()` = a read-only glance at the raw uploaded sheet (so the user can see their column names/positions); (2) `previewMap()` = one **card per SKU field we need** (★ Main [UPC/Item ID], ASIN, Product Name, Brand, Amazon Price, Qty/Case, Cost/Case, Pack qty) laid out in a **wrapping responsive grid** (`repeat(auto-fill,minmax(205px,1fr))` — NO horizontal scroll). Each card = field label + a `dd("fieldmap",…)` dropdown that picks which uploaded column feeds it + one sample value. `columnForField()`/`setFieldColumn()` keep `col_map` = column→field for the backend. Fields include the bulk-template columns that come from the sheet: ★ Main, ASIN, Product Name, Brand, **Amazon Price** (→ AmazonPrice), **Qty / Case** (→ QtyPerCase), **Cost / Case** (→ CostPerCase), Pack qty. **Steps are display-only** (no click-to-navigate — `clickable=false` in `stepper()`; use the Back button). **Step 3** shows a CSS-only indeterminate bar (`cpoIndet`) with **no render loop**. Open menus **reposition on scroll** and ignore the menu's own internal scroll (so scrolling the option list no longer closes it); they close only when the trigger scrolls out of view. **Brand auto-detect:** on upload, if a Brand column is present, `brandMode` defaults to `"column"` so brands come from the file automatically; single-brand mode prefills mfr/prefix on blur/Enter (`loadBrands`). `resolve_brands` now AI-suggests the manufacturer for **in-catalog** brands too. A **"For Amazon" toggle** (`S.forAmazon`, default Yes) drops the ASIN requirement when No, removes ASIN from the column dropdown options, and disables shadow creation → a Main-only SKU with no ASIN; `requiredMissing()` = Main-id always + ASIN only when For-Amazon. **Step-2 "What to create"** has just **two** toggles: **Main SKU** and **Child SKUs** (= shadows `-FBA/-FBM` + kits `_QY`). The Kit toggle was removed — kits are data-driven: `normalize_rows` defaults `pack_qty` to 1 when the Pack-qty field is unmapped/blank, and `derive_rows` makes a `_QY{n}` kit only when `pack_qty > 1`. `collectConfig` sends `create.kit = create.shadow` so the single Child toggle governs both; For-Amazon=No forces Child off (no ASIN → no shadows/kits, Main only). **Dropdowns are render-free:** `dd()` emits only the trigger + registers its opts in `S.ddReg`; opening builds the menu in JS and portals it to `<body>` (`showMenu`/`closeMenu`).
- **Endpoints** (`routers/create_po.py`; JSON except preview): `POST /preview` (multipart → headers + sample rows + session token, plus sheet names + active sheet / header-row re-parse support), `POST /brands` (→ brand roster: status / manufacturer / prefix), `POST /generate` (full config → review groups + counts), `POST /export` (token + inline edits → JSON `{files:[{name,b64}]}` — the 3 templates **`bulk.xlsx` / `kits.xlsx` / `amz_shadows.xlsx`**; the UI downloads each separately), `GET /history` (recent export log), `GET /create-po/history/{export_id}/download` (re-download a past export's exact original files, no re-generation — see Changelog 2026-10-15). Config: `batch_type`, `create_by` (UPC/MPN), `company` (Ford Medical `-FBA/-FBM` | Turba `-FBATRB/-FBMTRB`), `create{main,shadow,kit}`, `col_map`, `brand_mode`+`brand_overrides`, `purchaser`/`sourcer`. `_session_index(sess, company)` rebuilds the session-cached catalog index whenever the currently-configured company differs from what's cached (fixes a stale cross-company index bug — see Changelog 2026-10-08b).
- **Derivation** (`services/create_po.py`): main = `prefix + (UPC-tail(6) | MPN)`; main existence by **UPC / UPC+leading-0 / MPN**, shadow/kit by **ASIN**; **ASIN-already-listed reuse wins** over UPC/MPN reuse; new brand → auto-unique prefix (always 3 chars) + AI-suggested manufacturer (best-effort Claude call, empty for unknown/fake brands). **Single-brand mode** resolves the brand through the roster (`brands.get`) and only overrides mfr/prefix when the user typed them.
- **Brand auto-fill**: `services/sc_reference.py` is a local "SellerCloud memory" — `sc_brand_prefix` (brand→prefix, company-scoped, mode of `_lead_prefix(main)[:3]` capped at 3, with manual exceptions in `_MANUAL_PREFIX` for cases no count heuristic can resolve, e.g. Dove→DOV vs the umbrella Unilever code ULV) and `sc_manufacturer` (manufacturer→canonical name + mode purchaser/sourcer, matched accent/case/spacing-insensitively via `_mkey`, ranked STRONG-over-WEAK by SKU count) built from a full Azure scan on startup (`build_reference()`, ~15s, company-scoped). `resolve_brands(..., company=)` prefers `sc_reference.prefix_for`/`lookup_manufacturer` over the live index; a newly-resolved brand/manufacturer is saved back (`save_brand_reference`) on export so it resolves instantly next time. Purchaser emails are normalized to `<name>@fordmed.com` via `brand_map.fordmed_email()` (the legacy `brand_mappings` table / `services/brand_map.py` Excel-import fallback is retained for brands `sc_reference` hasn't seen yet). **UI:** the step-2 brand panel is per-brand **cards** (Manufacturer / Prefix / Purchaser / Sourcer, all editable + auto-filled, plus the brand NAME itself is editable and flows through to the export's BrandName column); single-brand mode has matching fields.
- **Export format** (`build_files`): matches the user's real templates byte-for-structure — **bulk.xlsx** = sheet "Bulk" (17 cols, blanks as `None`) + `BULK_COL_WIDTHS`; **kits.xlsx** / **amz_shadows.xlsx** = single "Sheet1". The bulk file emits **one row PER SKU** (main + `-FBA`/`-FBM` shadows + `_QY{n}-FBA`/`-FBM` kit shadows), **grouped by type — all mains first, then all FBA, then all FBM**, each with all 17 columns computed per the user's rules: **ProductName** = `Brand + title + (UOM)` for CPG, `Brand + MPN + title + (UOM)` for Medical — where `title` prefers an **AI-cleaned description** (`clean_name`, via the shared Abbreviation Library — unknown abbreviations in a vendor title are expanded by AI and the new abbr→full pair is saved back to the library) over the raw vendor title, and the UOM-suffix rule depends on context: a **plain (non-kit) shadow reuses the existing main's own title byte-for-byte** (including its own trailing UOM parenthetical) when the main already exists on SellerCloud; a **kit unwraps** the main's trailing `(UOM)` into plain text and appends the kit's own `(Pack of N)`; a brand-new main's title gets the count/pack phrase parsed straight from the vendor TITLE (`_title_pack`) rather than the generic amz-pack-based UOM. A wholesale CASE quantity stated in a vendor title (e.g. "CS/6", "4/CASE") is never surfaced in the generated title — it's a shipping unit, not a retail pack, and is explicitly stripped; a genuine separate lower-UOM count in the same title is still kept. **ASIN** only on FBA/FBM; **UPC/ManufacturerSKU/QtyPerCase/CostPerCase** on EVERY sku; **QTY** = main 0 / non-QY shadow 1 / kit N; **AmazonEnabled** = "TRUE" on FBA/FBM else blank; **FulfilledBy** = "Amazon" for `-FBA` else "Merchant"; **AmazonPrice** = FBA `round(buybox×1.2,2)`, FBM `round(FBA×1.1,2)`; **AmazonPriceUseDefault** = "FALSE" on FBA/FBM, blank on the main; **CostPerCase** rule: costcase, else unitcost×qtycase, else unitcost; **BrandName** = canonical case-sensitive; **ProductGroupName** = "CPG" or blank (medical); **ManufacturerID** = manufacturer name; **SOURCE_LEAD/Purchaser** per-brand. Connection files: **kits** ParentSKU=`{main}_QY{n}{suf}`, ChildSKU=main, QTY=n, InventoryDependantOption=Independent(FBA)/All_Components(FBM); **amz** ParentSKU=main, ShadowSKU=`-FBM`/`-FBA`, CompanyID = **164 Ford Medical / 258 Turba**. A new FBA/FBM child of an already-existing main reuses the main's real stored title (not the vendor's own, possibly-wrong, raw title), with just the UOM-suffix swapped. A reused shadow whose SKU stem doesn't match the freshly-generated main (`fba_mismatch`/`fbm_mismatch`) is flagged with a warning modal rather than silently trusted — this can legitimately happen when an ASIN's existing shadow predates a brand/prefix change. **File naming + logging**: `build_files(results, config, tag)` names files **`Bulk_<ID>_<date>.xlsx` / `Kits_…` / `AMZ_…`**; the export route generates `export_id = uuid4().hex[:6].upper()` + `date.today()`, and only includes the kit/amz files when they have data rows. Each export is logged to **`sku_exports`** (`services/sku_exports.py`: id, export_id, export_date, created_at, company, batch_type, total_mains/fba/fbm/kits, files JSON, **`files_blob`** — the full generated bytes, added 2026-10-15, so a past export can be re-downloaded exactly via `GET /create-po/history/{export_id}/download` with no re-generation). The `/export` response returns `export_id`+`export_date`; the UI shows "✓ Exported · <ID>" and hides the Kit/Amz cards when those files aren't produced. The history list scrolls inside a fixed-height container (`max-height:360px`) instead of growing the page indefinitely, and each row has a "↻ Re-export" button.
