# Walmart Catalog

## What this does

The app's first step toward supporting marketplaces beyond Amazon — a "Walmart Catalog" section (sidebar, under a new "Marketplaces" group) offering an Offer Analysis workflow against Walmart's own catalog/pricing data, parallel in spirit to the Amazon "Offer Analysis" feature (`docs/features/offer_analytics.md`) but built around Walmart's much thinner public API surface (no live per-item fee-estimate API; referral/fulfillment fees are a static published rate table, not queryable live).

## Architecture

- `services/walmart/` package (mirrors `services/spapi/`'s structure): `config.py` (`load_walmart_credentials()`, production-by-default unless `WALMART_SANDBOX=1`), `auth.py` (`WalmartTokenManager` — OAuth2 client_credentials, HTTP Basic auth, 900s token TTL, no long-lived refresh token so it must re-auth constantly, unlike SP-API's LWA), `catalog.py` (`WalmartCatalogAPI.search()` wraps `GET /v3/items/walmart/search` by query/upc/gtin/ean/isbn; `best_match(items, query, min_ratio=55.0)` + `.search_best()` fuzzy-score every returned item's title via `rapidfuzz.fuzz.token_set_ratio` and only accept the top scorer if it clears the floor AND carries a `price` AND doesn't conflict on size (reuses `services.analytics.matcher._size_mismatch` verbatim) — a raw keyword search hit needs this relevance floor, an exact-identifier UPC hit does not and uses the simpler `search_one()`), `offer_analysis.py` (`compute_offer_analysis()`: `net_profit = walmart_price - vendor_cost - referral_fee - other_fees`, referral fee from a representative, non-exhaustive `REFERRAL_RATE_TABLE` keyed by substring-matched category with a `DEFAULT_REFERRAL_RATE=0.15` fallback).
- `routers/walmart.py`: `GET /api/walmart/status`, `POST /api/walmart/search`, `POST /api/walmart/offer-analysis` (body `{items:[{upc?, query?, vendor_cost, category?, other_fees?}]}`, searched concurrently via `asyncio.gather`; branches on `upc` (exact `search_one`) vs `query` (fuzzy `search_best`)).
- **UI**: a textarea of `UPC-or-title, Vendor Cost[, Category]` rows (auto-detects per row whether the first token is a UPC or a title/keyword query — tab-separated tried first so a pasted title containing commas isn't split apart), a results table (UPC/Walmart ID/Title/Match score/Walmart Price/Vendor Cost/Referral Fee/Net Profit/ROI/Note), CSV export.

**Changes this session (2026-09-29b) — Walmart Offer Analysis: title search now fuzzy-matched, not "trust the first result" (first live credentials confirmed working, and surfaced a real bug):**

- **Root cause**: `WalmartCatalogAPI.search_one()` (`services/walmart/catalog.py`) just returned `items[0]` with zero relevance check. - **Fix**: new `best_match(items, query, min_ratio=55.0)` + `WalmartCatalogAPI.search_best(query=...)` in `services/walmart/catalog.py` — scores every returned item's title against the query via `rapidfuzz.fuzz.token_set_ratio` (already a project dependency), returns the highest-scoring item ONLY if it clears `MIN_TITLE_MATCH_RATIO` (55), else `(None, best_score)` — a genuinely bad search returns "no match," never a guess. `routers/walmart.py`'s `walmart_offer_analysis` now calls `search_best()` for `query`-based rows (title search) and keeps `search_one()` only for `upc`-based rows (an exact barcode hit is trusted the same way a UPC match already is for Amazon — no fuzzy check needed there). The match score is threaded through as `match_score` in the response; when nothing clears the floor, the `note` explicitly reports the best score found (e.g. "best title similarity: 37%") instead of a generic message.
- **UI**: new **"Match"** column in the Offer Analysis results table (`static/index.html`/`static/app.js`) — shows `"exact (UPC)"` for barcode rows, or the fuzzy score (e.g. `"86%"`) for title rows, or `"—"` when nothing matched; added to the CSV export too. Panel help text updated to explain the relevance floor.
- **Verified**: a unit test reproducing the EXACT reported bug — feeding `best_match()` the two real titles from the report (the NYX eyeliner + the correct L'Oreal item) for the query `"L'Oreal Paris Eye Makeup Remover"` — confirms it now picks the correct L'Oreal item (score 85.7) instead of the NYX eyeliner that plain `item[0]` would have returned, plus a control case (a genuinely unrelated query) correctly returns no match rather than a low-confidence guess. Also re-ran the full-app smoke test (throwaway server, no real credentials in this session's own `.env`) to confirm the new code paths don't crash and the UI changes are present.
- Scope: `services/walmart/catalog.py` (`best_match`, `search_best`, `MIN_TITLE_MATCH_RATIO`), `routers/walmart.py` (`walmart_offer_analysis` branches on upc vs query), `static/index.html`, `static/app.js`. **Needs a backend restart** (Python changes) + browser hard-refresh.
