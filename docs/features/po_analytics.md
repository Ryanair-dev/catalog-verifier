# PO Analytics

## What this does

Analyzes a received (or about-to-be-received) SellerCloud Purchase Order's FBA/FBM shadow SKUs for profitability, producing a 2-sheet Excel report (Analytics + PO). Two ways to run it: (1) on-demand, type a PO number and download immediately ("Analyze a PO"); (2) a day-before-ETA automation — add a PO to a watchlist, and the system automatically re-runs the analysis and emails it to chosen recipients the day before (or on/after) its tracked ETA on the Inbound Shipments Monday.com board, read via a same-day-fresh Azure SQL mirror (zero Monday API cost).

## Architecture

- `services/analytics/po_analytics.py` — `gather(po_numbers, require_received=True)` pulls the SellerCloud PO, auto-resolves a cancelled PO to its real split via `sellercloud.Purchase.SplittedFromPOId`, resolves each line item's Main SKU → FBA/FBM children via the SellerCloud catalog snapshot/Azure, and reads live Keepa/SP-API pricing data; `enrich_and_build(gathered, on_progress=None)` builds the final 2-sheet (Analytics + PO) workbook, reusing the same Keepa/SP-API enrichment machinery as Offer Analytics (`services/vendor_offers_template_export.py`'s `enrich_asins`, `_fba_total_by_asin`, etc.) — see `docs/features/offer_analytics.md`/`docs/features/vendor_offers.md` for that shared machinery.
- `services/monday_eta.py` — reads Azure's own Monday.com mirror (`monday` schema, NOT the live Monday API) for board `581141334` "Inbound Shipments". `fetch_inbound_items()` returns one row per active board item: `{item_id, po_number, eta_to_warehouse, status, actual_arrived_date, vendor, goods, amount, item_updated_at}`. **Critical correctness point**: the PO number MUST be read from the `link` column's parsed value (`link_text_value`), never `items.name` — two real items on this board can share the same `name` even though only one of them is the real split's own tracking item. Column IDs are the composite string `"board_id:<id>|column_id:<name>"`.
- `services/po_automation.py` — the day-before-ETA automation orchestration. Tables: `po_eta_automation` (per-PO tracking: last-seen ETA/status/vendor/goods/amount/sent-state/archived report), `po_automation_watchlist` (user-curated PO numbers to watch, with an optional per-PO `recipients_json` override), `automation_recipients` (generic `{tool: [recipients], enabled}` table shared with any future automated tool — only `po_analytics` is wired to a real trigger). `check_and_trigger()`: pulls the live Monday mirror, upserts tracking for every WATCHED PO only, then fires (`gather(require_received=False)` → `enrich_and_build()` → `services/graph_mail.py send_mail()`) for every watched PO whose current ETA falls in `[today − 3 days, tomorrow]` and hasn't been sent yet (a single bound covering both the day-before golden rule and a same-day-revision catch-up). Once sent for a PO, never re-sent even if the ETA moves again. Excludes POs whose Monday status is already `Received`/`Cancelled`. `refresh_tracking_for(po_numbers)` pulls tracking for specific PO(s) immediately (used right after Add-PO, so the UI never has to wait for the next scheduled/manual check — see Changelog, 2026-10-16). Scheduled once daily at 12:00 America/New_York (`start_scheduler`/`_loop`, DST-safe 5-min re-check granularity).
- `services/graph_mail.py` — thin Microsoft Graph `sendMail` wrapper (`/me/sendMail`, since `/me` already resolves to the `datateamautomations@fordmed.com` identity directly), used only by `po_automation.py`'s automated send.
- `routers/po_analytics.py` — `POST /po-analytics/start` (on-demand run, background job, poll/download pattern — see `docs/infra/job_persistence.md` for how this job type wires into the shared restart-survival system) + the automation endpoints: `GET/POST /po-analytics/automation/watchlist`, `DELETE /po-analytics/automation/watchlist/{po_number}`, `GET /po-analytics/automation/status`, `POST /po-analytics/automation/check-now`, `GET /po-analytics/automation/archive/{po_number}/download`.
- UI lives in the Toolbox panel's "PO Analytics" sub-tab (moved there 2026-10-15, see `docs/features/toolbox.md` for the Toolbox shell itself): an "Analyze a PO" card (on-demand run, left/top), an "Add PO" card (adds to the watchlist, with a recipient picker — a popup list, click-to-choose, not checkboxes, that opens from a static "Choose recipient" button), a "Status" card (watched/sent counts + Refresh), an "Awaiting Analysis" list (PO#+Vendor, hover for full detail), and an "Archive" list (download the exact report that was emailed).
